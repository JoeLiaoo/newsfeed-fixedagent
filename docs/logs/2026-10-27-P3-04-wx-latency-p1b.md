# P3-04 / P1-B iLink 入站短事务租约 · 2026-10-27

## 做了什么

- `notifications/inbox.ts`：按账号领取 60 秒轮询租约，在事务外调用 `getupdates`，提交前复核 Bot、收件人、绑定版本、owner、generation 和数据库时钟下的到期时间；入站去重、`poll_position`、cursor、context、恢复状态和阅读入队同事务提交。租约若在写入期间过期，整笔写入回滚。响应后崩溃由下一轮从旧 cursor 重读，重复上游 ID 由原唯一约束去重。
- `notifications/ilink.ts`：39 秒网络上限保持，轮询请求组合 worker 停机信号，可在停机时中止。
- `notifications/binding.ts`：重绑时清除旧租约；解绑删除账号并递增绑定版本，两个路径与租约事务按原有用户 advisory lock 串行。
- 首次连接问候发送移至入站提交之后，并在发送前及回写时复核绑定版本；问候 ID 保持幂等。分钟调度、P1-A 的 `poll_position` 与 wake 行为、模型并发／预算不变。

## 文件与决定

追加迁移 `0222_member_ilink_poll_lease.sql`、`0223_member_ilink_poll_lease_expiry.sql`、`0224_member_ilink_poll_lease_generation.sql`，每个在线迁移只含一条语句。涉及源码为 `notifications/{inbox,ilink,binding}.ts`；新增 `tests/ilink-poll-lease.test.ts`，扩展 `tests/ilink-protocol.standalone.test.ts`；更新 `docs/{P3-OPERATIONS,IMPLEMENTATION}.md` 与待发布员工更新条目 `site/changelog/pending/wx-ilink-latency-p1b.json`。未运行 `changelog:apply`。

租约的 60 秒按 39 秒客户端超时加 21 秒响应解析与提交余量选取。本地合成单条入站加业务入队的三次提交分别测得 63、168、69 毫秒；这不是生产 p95，也没有验证接近 20 个账号或大批量响应时的余量。租约记录 owner UUID 与逐次递增 generation；重绑后即使 Bot ID 相同，旧结果仍被绑定版本及 owner 拦截。
