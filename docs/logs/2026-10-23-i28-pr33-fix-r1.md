  - `docs/IMPLEMENTATION.md`、`docs/README.md`：状态与索引同步。

- 实际完成：
  - 复核意见（P2）：默认展开的分组第一次点击收不起来。`toggle` 原先只翻转 `current[id]`，而分组没有手动状态时 `current[id]` 是 `undefined`，`!undefined` 为 `true`，于是第一次点击把分组写成展开，要点第二次才收起。现在切换以屏幕上显示的值为准（含 pathname 推导出的默认展开），第一次点击即收起，下一次点击再展开。
  - 深链默认展开、`hidden` 与 `aria-expanded` 的口径保持不变：分组仍只在自己持有当前页时自行展开；收起时子项列表仍带 `hidden`，不在键盘的可达范围内。

- 关键决定及理由：
  - 规则放在 `nav-state.ts` 而不是 `NavGroups.tsx`：桌面与手机两处共用同一份纯函数，既没有第二套状态，也能被 `node --test` 直接验证（`.tsx` 需转译，纯 `.ts` 不需要）。
  - `toggle` 传分组而不是分组 id：取反需要知道该分组的默认展开状态，只传 id 就拿不到；两处调用改完后签名一致，桌面与手机仍是同一套规则。
  - 手动状态仍优先于默认：读者收起过的分组在换页后不会被默认重新展开，这与复核前的行为一致，本次只修“第一次点击”的取值。
