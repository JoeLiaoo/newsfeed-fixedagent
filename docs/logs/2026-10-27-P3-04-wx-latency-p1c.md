# P3-04 / P1-C 逐 Bot 持续入站轮询 · 2026-10-27

## 做了什么

- 新增 `modules/membership/notifications/inbox-queue.ts`：每个灰度账号以 pg-boss 单独领取一份轮询任务，`batchSize:1`、本地及跨 worker 同组并发上限 20。成功或可重试失败后，在 P1-B fenced 提交的同一短事务保存下一份任务；分钟任务仅发现新绑定、补缺及恢复过期租约。每 Bot 只允许一个有效租约和网络请求。
- 调整 `notifications/inbox.ts`：把单账号轮询复用给旧分钟模式和快速模式；分钟任务排除明确灰度账号。快速空响应做 1–30 秒有界退避，网络错误和限流做带抖动的指数退避（最高 60 秒）；`requires_rebind` 停止，`needs_interaction` 继续监听入站。近失效提醒移为独立每小时任务。
- 调整 `modules/membership/package.json`、`site/modules/server.ts`、`.env.example`，增加默认关闭的 `P3_ILINK_FAST_POLL_ENABLED` 和必须明确填写的 `P3_ILINK_FAST_POLL_USER_IDS`。增加待发布员工更新 JSON，未运行 `changelog:apply`。
- 更新 `docs/P3-OPERATIONS.md`、`docs/IMPLEMENTATION.md` 和文档索引；P3-04 仍未勾选。

## 关键决定与风险

短策略队列以员工 UUID 作 `singletonKey`，因此每个账号最多有一份待领取任务，正在运行的任务可在 cursor 提交时创建其后继；所有补漏入队同样按账号 advisory lock 检查已有任务。pg-boss 跨 worker 同组并发上限 20，超过的账号按创建顺序等待。快速请求仍沿用 60 秒租约、39 秒客户端超时与绑定版本 fencing；不提高模型并发或费用预算。

剩余风险：上游快速空返回与限流的真实分布未知，20 Bot 的生产连接数和 CPU 压力未测；分钟补漏在任务异常失败后可能带来最长约一分钟的接续空档。回退须停并排空快速请求，再用关闭开关的 worker 运行旧分钟任务；已提交 cursor 保留。不可与不识别 P1-B 租约的旧进程并跑。
