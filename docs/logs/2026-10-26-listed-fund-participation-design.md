# 方案：地区「上市公司参与股权基金」专家（MVP）

**目标：** 员工输入省或市（及可选年份/代码池），在专家平台跑出**披露可得范围内**的「上市公司参与股权基金」报告；不宣称全市场工商穿透全量或 LP 全口径。

**产品名（员工可见）：** 地区上市公司基金参与
**slug 建议：** `listed-fund-participation`
**状态：** `available`
**模式标签（员工可见）：** 披露驱动的基金参与分析（内部 execution 可用 `listed_fund_participation` 或 slug 特判，仿 `sector-peer` / `frontier-podcast`）

## 边界（必须写进 skill / 报告页眉）

- 覆盖：**有公开披露（公告）** 的上市公司参与/出资设立/合作股权基金记录；不是悟道式全量备案穿透。
- 数据组合：平台企业信息查询（新华）做主体身份核验 + 公告检索/正文抽取 + 基金备案公示主数据对齐。
- **禁止**在员工文案出现「新华 / 巨潮 / 中基协 / DeepSeek」等品牌；缺口用能力口径描述。
- 未知金额/角色/备案号保持「未提供」，不记零、不脑补。
- 不开放国企 LP 全口径排名（另一条产品线）。

## 输入

| 字段 | 必填 | 说明 |
|---|---|---|
| `region` | 是 | 省或市级行政区名称，如「浙江省」「杭州市」 |
| `startDate` / `endDate` 或年份 | 建议 | 默认近 3 个自然年；披露日过滤 |
| `stockCodes` | 否 | 6 位 A 股/北交所代码列表；有则优先 |
| `maxIssuers` / 预算 | 否 | 默认上限（如发行人 40、公告 200、PDF 抽取 80），超限写入缺口 |

**发行人宇宙解析顺序：**
1. 若提供 `stockCodes` → 用之；
2. 否则查平台内置「地区→上市发行人」种子（MVP 至少含浙江/杭州可扩展的静态表或配置；表源与日期写入报告）；
3. 仍空 → 任务失败，提示需补充代码或联系管理员扩种子。

勿假装能从网页「搜出一个省的全部上市公司」且完整。

## 流水线（服务端确定性为主）

1. **解析发行人集合**（代码、简称、可选注册地）；注册地与 `region` 不一致的标「地区待核」仍可跑，或按配置过滤。
2. **公告采集（自建适配器，非员工可见）：** 按代码查信息披露公告列表；优先类别/关键词覆盖「对外投资」「与私募基金合作投资」「参与出资」「产业基金」「股权投资」等；分页读全；存 title/date/url/announcementId。
3. **正文抽取（尽力）：** 下载 PDF，抽合伙人/认缴/实缴/基金名/管理人等表或段落；失败则该条仅保留元数据+「正文未解析」。
4. **备案对齐：** 用基金名称等对基金产品公示主数据做匹配；命中填备案号/管理人/状态；未命中标缺口（不得称「未备案」）。
5. **身份核验：** 对出现的上市公司、基金、管理人名称走现有企业信息查询（画像/检索）；冲突保留双源。
6. **汇总表（代码算，不算模型）：**
   - 参与明细：发行人｜代码｜基金｜备案号｜管理人｜角色｜认缴｜实缴｜披露日｜公告链接｜纳入/排除原因
   - 发行人热度、管理人热度、共投基金（≥2 家发行人）
   - 缺口/未解析/预算截断清单
7. **叙述：** 模型仅基于表写摘要；失败则无摘要仍出表。
8. **产物：** 与全景/播客一致——Markdown 底稿 + sandboxed HTML 预览；任务结果标完整/不完整。
