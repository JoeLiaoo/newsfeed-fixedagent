# P0-B · iLink 延迟基线 · 2026-10-27

范围：外部方案 P0-B，只补服务端测量；P3-04 真实双员工与跨日验收仍未完成。本分支不合并、不部署、不变更生产开关。

## 实施与文件

- `modules/membership/notifications/{ilink,inbox}.ts`：在 `getupdates` 响应返回后立即取 `received_at`，以单调时钟记录轮询耗时；不再将长事务的 `now()` 当作真实接收时刻。账号最近互动时间使用同一响应边界时间。
- `modules/membership/conversation/{latency,replies,agent-worker,knowledge}.ts` 与 `modules/membership/knowledge/service.ts`：记录路由领取、Hermes／知识库模型段、发送请求的耗时、路由、状态和可用用量；详细日志只在新开关为 `true` 时输出，排除正文、账号、凭据和游标。
- `modules/membership/migrations/0218`～`0220`：三个可空、无默认值列 `received_at`、`send_started_at`、`accepted_at`，不回填历史。`accepted_at` 仅在 iLink 明确受理时写入。
- `.env.example`、`docs/P3-OPERATIONS.md`、`docs/IMPLEMENTATION.md`、`docs/README.md`、`site/changelog/pending/wx-ilink-latency-metrics.json`：默认关闭、语义、运维与待发布说明。
- `modules/membership/tests/wx-latency.test.ts`、`wx-latency.standalone.test.ts`：延迟渠道响应、失败和 unknown 发送、旧式插入兼容，以及日志字段白名单／默认关闭。

## 决定与边界

详细日志只含内部随机／入站关联 ID、阶段、路由、状态、毫秒耗时和已知 API 调用／token 用量。轮询请求 ID 与逐消息 ID 不相同，因此服务端无法由此推导手机发送时间；渠道 `accepted` 也不是手机显示。保留现有发送事务、队列和额度语义；进程崩溃后仍可能存在不明发送结果，不自动重发 unknown。历史记录的三个新时间字段保持 NULL。
