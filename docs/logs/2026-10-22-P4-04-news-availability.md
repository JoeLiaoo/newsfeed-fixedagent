# P4-04 员工资讯不可用现场修复

日期：2026-10-22（Asia/Shanghai）
范围：火山云 `citic-newsfeed-prod`；P4-04 仍需员工本人验收，保持未勾选。

## 现象与原因

- 员工反馈新账号看不到资讯，热点与个人日报无法加载。现场数据库初始有 18 个已启用信源，但文章数为 0；生产 `COLLECT_ENABLED`、`MODEL_CALLS_ENABLED` 均为 `false`，因此没有资讯产出。
- 有效会话访问 `/api/site/hot` 返回 200，但访问 `/hot`、`/hot.data` 返回 503；服务端日志中的下游 API 状态为 401。HTTP 入口直接导入请求上下文源码，React Router 的服务端构建打包了另一份模块，两份 `AsyncLocalStorage` 实例未共享，路由转发 API 时丢失 Cookie。
- 今日已有两份空日报快照在第一篇资讯进入展示库之前生成。日报按用户、日期和关注版本固定，采集恢复后不会自行填充已有快照。

## 改动与关键决定

- 在 `apps/web/app/lib/request-context.server.ts` 通过进程级 `Symbol.for` 共用请求上下文存储，保持各请求隔离。线上页面使用独立热修复版本 `4a243981aa731e9860c203beead926872d18327c-webctx1`，基于原发布源码仅修改该文件；原发布目录保留。
- 原始镜像标签已从原发布源码重新构建，热修复与原始版本均有独立镜像标签；回退页面时应使用原发布目录的 Compose 配置，仅重建 Web 容器并复核登录态和健康状态。
- 将服务器受限 `.env` 中的采集与模型开关设为 `true`，默认模型配置为 DeepSeek Flash。服务器 `.env` 修改前备份至 `/opt/citic-newsfeed/shared/.env.before-news-20261022`，权限保持 `0600`；密钥继续从只读凭据目录读取，未写入仓库或日志。仅重建/重启新平台的相关容器，未操作其他服务。
- 只删除今日生成于首批资讯入库前、条目数为 0 的两份空日报快照，使下次访问按当期关注重新生成。未改动其他日期或已有内容快照。
- `P3_GP_SYNC_ENABLED`、`P3_NOTIFICATIONS_ENABLED`、`P3_DELIVERY_ENABLED` 继续为 `false`。

## 最小验证

- 18 个信源开始抓取；观察时 96 篇文章入库、59 篇形成展示记录，12 个信源成功、6 个信源显示采集错误。
- 使用立即撤销的短时测试会话验证：修复前 `/hot` 与 `/hot.data` 为 503；修复后经 HTTPS 入口访问首页、热点、热点数据、实时新闻、健康接口均为 200。测试会话已删除。
- 管理员今日个人日报重建后有 17 条。热点页正常加载，但当时热点榜为 0 项；规则要求至少两个独立参与方，目前没有达标事件，不能为填充榜单放宽事实规则。
- 最新一个已审核账号目前关注标签数为 0：首页按产品流程返回 302，引导到关注设置；该账号的关注设置、实时新闻和热点页面均返回 200。此账号的个人日报需本人先选择并保存至少一个方向。检查仅输出数量和 HTTP 状态，未读取账号资料或文章正文。
- 未做浏览器端真实员工账号验收、跨日投递或全量测试。
