本文是工程与运维说明，按服务器实际配置记录数据源名称、工具名与主机；员工可见的页面、任务错误、Markdown 及 HTML 产物只说明能力（「一层对外投资核查」「对外投资全景图」「赛道同业竞争看板」「前沿播客」「文本任务专家」「平台企业信息查询」），不出现数据源或模型品牌名。

## 一层对外投资核查（既有能力，目录入口已隐藏）

内置专家使用新华财经 `zjs_company` MCP 查询已确认主体的工商画像与一层直接投资，并由 DeepSeek 整理带证据的底稿。页面与产物明确说明查询仅覆盖一层；工具字段和时间语义见 [P0 数据矩阵](P0-DATA-MATRIX.md)。该专家不再作为目录入口提供，其能力口径保留在导入技能的三工具模式中。

| 能力 | 状态 | 当前范围与边界 |
|---|---|---|
| 实体检索并先锚定 ID | 部分支持，真实 schema 待核 | 员工先从名称候选中选择；代码按候选是否带信用代码，向画像工具发送 `query_type=credit_code` 或 `query_type=company_name`（用候选的准确登记名称），并核验返回的主体 ID、名称和信用代码。信用代码查询回答 `not_found` 时改用名称重查一次（不是等抛错才回退）。`company_id` 查询类型不受支持已确认（PDF 与实时 schema 都不列），实现已改用受支持的查询方式；见 [P0 数据矩阵](P0-DATA-MATRIX.md)。2026-10-23 实测：候选检索返回体为 `{result:{total, results[]}}`，是名称子串匹配；原样名称无匹配时依次尝试去掉尾部括号与企业形式后的短名，命中即标记为近似候选供员工确认。错误分为“未匹配到主体”“返回行缺少主体 ID”“响应结构无法解析”三类，不再混为一类。 |

| 按控股／参股逐层穿透 | 缺失 | 目前不会递归查询，也不声称全量覆盖集团链条。 |

| 上市公司终止及代码标注 | 缺失 | 当前工具适配未实现上市主体判定。 |
| 合伙基金备案、公司制基金识别及组合披露终止 | 缺失 | 未接入基金备案工具；不能把无返回字段当作未备案。 |

## 对外投资全景图

全景图专家把参考 skill「单体分析09-对外投资全景图核查」的终止条件与穿透规则落在平台已授权的八项能力上：主体名称候选检索、企业基础画像、对外直接投资、股东信息、注销吊销信息、历史名称、年报基础信息、年报对外投资。参考 skill 依赖的另一套数据源工具（含基金备案与历史退出查询）在本平台没有对等能力，凡规则需要这些数据的，一律在底稿的缺口清单里写明，不推断、不跳过。

### 主体候选检索

- 员工输入的企业名称先按原词检索（每页 10 条，最多翻到第二页）；知名上市公司往往有大量以它命名的分支机构，母公司可能不在第一页，继续翻页才能看到它。
- 没有与输入词完全一致的主体时，再按法律形式反推候选所依附的母公司登记名去问一次（分支的登记名一般是母公司登记名加自己的名字）；这些名字只当检索词用，是否存在由服务端回答，员工最终确认。单次实体检索最多 5 次调用，候选最多 12 条。
- 候选排序：与输入词完全一致 → 登记名以输入词开头（短的在前，母公司排在它自己的分支机构之前）→ 其余。候选带登记类型与「依附于哪个候选」，页面据此写明「该候选是分支机构，通常没有自己的对外投资记录」或「该候选的登记名称建立在「X」之上，可能是分支机构」；没有候选的登记名包含输入词时，页面说明这是近似候选。
- 专家页和 `/tasks/:id` 的关系标签还参考员工输入词：候选中有股份公司形式、被分支登记名引用，或登记名恰为输入词加公司形式且有 18 位信用代码的母公司候选时，同一品牌前缀下的其他「有限公司／有限责任公司」名称提示为「分支机构」。同名候选仅一条显示「母公司候选」，优先有 18 位信用代码的记录；近似候选不显示关系标签。这只是名称线索，不证明股权控制或法律上的分支关系，仍由员工确认主体；品牌提示不写入 `branchOf`，不改变候选排序。
- 候选只保留带主体 ID 的行：ID 是后续画像核验的比对依据。

### 运行预算与断点续跑

- 默认预算：层级 4、主体 25、实际查询 90 次、单节点处理 20 条关系。起点画像核验计入 90 次，员工确认主体前的名称候选检索不计入穿透预算；已从检查点恢复的读取不消耗本次查询预算。达到层级上限后不读取下一层主体详情；因层级、主体数、调用次数或单节点上限跳过的关系不进表格，逐主体缺口清单注明未处理数量。恰好读完单节点上限数量不误报截断。
- 每个主体的读取结果按（任务，主体，读取类型）落入 `member_expert_panorama_checkpoints`；同一任务重试时复用已读结果，包括已验证的起点画像，不重复查询。检查点只供服务端恢复任务，员工没有 JSONL 下载接口或 UI。
- 单个主体读取失败只影响该主体：它留在底稿里并带缺口说明，其余主体继续处理。任何预算截断或单体读取缺口都会在报告和任务卡片标为「结果不完整」；错误说明使用平台能力文案，不回显原始服务错误文本。
- 服务端对某主体回答 `not_found`（无此记录）时写成对应缺口，不写成「分页未读完」，也不据此断定该主体没有对外投资。
- 底稿的文字摘要由模型写；摘要一步失败（模型未配置、输出不可用、调用结果未知、服务端拒绝）时，底稿仍然生成，摘要位置写明缺的是哪一部分，缺口清单同步记一条，错误码与中文原因按模型侧的具体原因区分，不落到笼统的「请检查配置」。
- 成功的全景任务在专家页和任务详情页显示 sandboxed 单文件静态 HTML 预览，并提供 `.md` / `text/markdown` 底稿下载；预览与下载使用同一份 Markdown 草稿，HTML 不含脚本或外部资源。检查点仍保存在服务端供任务续跑，不作为员工下载产物。该实现已随 [PR #97](https://github.com/JoeLiaoo/newsfeed-fixedagent/pull/97) 合并（`aa1323a`），quality、PostgreSQL integration 与 docs links 检查通过，并随 2026-10-26 的 release `e2daacd` 发布到生产；真实员工产物验收仍未完成，见[发布记录](logs/2026-10-26-P4-pr96-pr97-deployment.md)。

### 底稿结构

逐层投资明细 → 有限合伙份额链 → 结构树（逐层持股，比例逐字引用）→ 全景汇总（存续公司／存续有限合伙／存续基金类主体、关键主体清单）→ 已退出对外投资（与存续分表）→ 年报披露交叉 → 缺口与待核清单 → 采集台账（断点续跑）→ 摘要整理 → 待核事项 → 使用说明。表格单元格只放数据与短标签，判断依据、剔除记录与能力缺口写进表注与缺口清单。

## 赛道同业竞争看板

员工输入一个企业或赛道名称，API 使用 `query` 保存原始文字（去掉首尾空白后至少两个汉字／拉丁字母或数字），可附备注；不要求工商主体确认。worker 为同业、阶段信号、境内资本事件和美国参考各执行一次固定查询（每次最多 5 条结果），请求结果正文；最多再抓取 3 个正文不足的结果页，随后由结构化模型整理证据并生成 HTML。单任务最多 4 次搜索、3 次抓取和 1 次模型请求；搜索与抓取与结构化整理共用已有的 `deepseek` 服务收据和日／时／分预算（用途分别记录为 `expert_search`、`expert_fetch` 与 `expert`），不新增预算服务行或数据库迁移。接口密钥只从服务端 models 凭据读取；员工页面和产物只说明“公开资料检索”，不显示供应商名称。模型只可引用本次搜索返回的来源 ID，HTML 渲染器还会剔除未检索 ID 的断言，URL 由已检索来源提供；日期采用结果元数据日期，不推断发生日。服务关闭、密钥缺失或模型停用时任务明确失败，不成功生成空看板。

看板三主区是「同业是谁」「发展到哪（公开阶段信号）」「资本市场认可」，以中国同业、人民币融资与境内交易为主，美国同业／融资只作参考带。另列检索缺口与「不构成投资建议」。每项结论链接其来源页并显示来源日期或「未提供」；没有可引用证据的分区显示「未披露／未检索到」，不会用模型填空。检索到空集时保留看板结构并说明未检索到来源；检索成功不代表市场覆盖完整。企业／赛道消歧尚未实现，输入词原样检索。内部 IC 笔记、未披露估值和真实 LP 管线不纳入。产物沿用专家任务的本人鉴权、七天保留与 HTML 下载／沙盒预览接口。

## 前沿播客（公开播客检索与摘要）

员工输入一个话题（2–100 字，中文、英文或数字），API 用 `query` 保存原始文字；不要求企业实体确认，不收任务材料。worker 先以原词和另一语言关键词分别检索（`/api/v1/search`），按 slug 去重并交错排列，再读取所有候选单集（`/api/v1/episodes/:slug`，每批并行 3 集），收录全部可读取且符合中文正文要求的节目，写出网页摘要与 Markdown 产物。常见话题由固定词对扩展；其他话题由现有专家模型只翻译检索词。模型不接触或改写节目正文。

| 环节 | 平台行为 | 边界 |
|---|---|---|
| 读取方式 | 服务端固定主机的普通 GET，不需要账号、密钥或配置；超时有上限（检索与单集各 20 秒） | 只读公开接口；不代理、不缓存、不改写服务返回的内容 |
| 字段 | 只用服务实际返回的节目标题、节目名、日期、时长、要点、摘要、导语、参与者与标签、来源链接；没有的字段写「未提供」 | 不推断事件日期，不把入库时间当作发生时间 |
| 语言 | 英文源节目优先取该库 `tldr_md`／`digest_md` 或其 alternate 字段里的中文正文，并逐集写明「公开播客文字库中文版」；缺少中文正文的英文集跳过 | 不把英文原文作为员工收到的主要正文，也不由平台补造译文 |
| 要点与摘要 | 原样呈现该库对原节目的整理稿；平台未逐条核验，页面与文件都写明 | 平台不补写节目未提及的事实、数字与结论 |
| 覆盖范围 | 上游可能返回近期节目子串匹配结果；员工 HTML 与 Markdown 不显示 partial 检索警告或检索窗口标签。记录读取失败数，英文源节目缺少中文正文时跳过 | 候选范围仍受上游搜索响应限制，双语结果不代表文字库全量 |
| 读不到节目 | 计数并写明；所有节目都读不到时，报出具体原因（服务不可用／超时／返回无法解析／该集已不在库中） | 不把服务故障读成「没有匹配到节目」 |
| 产物 | 网页摘要为单文件静态 HTML（内联 CSS），Markdown 保留全文；产物沿用专家任务的本人鉴权、七天保留与下载接口 | 网页预览在任务卡片的沙盒 iframe 中展示（无脚本、无同源、无外部资源） |

网页摘要按 beautiful-article / reacticle 的 `press`（书卷）主题排版：报头、导语、覆盖范围提示、目录、一集一节（章节号、标题、节目与日期等元信息、本集导语引文、来源提示、要点、摘要）、使用说明与版记。样式是主题 token 的内联 CSS，文档自带 CSP `default-src 'none'; style-src 'unsafe-inline'`；因为预览 iframe 是 `sandbox=""`，没有 3:4 封面（不允许取图片）、没有外部字体，也没有左侧目录栏，目录以书前目录的形态排在正文列里。

## 运行边界

- 格式及依赖检查通过的专家对获准员工公开；任务、上传材料、模型调用记录与产物仍归属于发起任务的员工，专家创建者不能读取其他员工的任务内容。
- 用户上传的 SKILL.md 或 ZIP 只作为文本保存和展示，不执行脚本、模板、网页或包内程序。ZIP 根目录仅允许 `manifest.json` 与 `SKILL.md`；限制压缩体积、条目数量、解压声明大小及路径。
- `SKILL.md` frontmatter 与 ZIP manifest 的 `tools`、`skills`/`dependencies.tools`、`dependencies.skills` 会结构化校验。未声明工具的自定义专家仍按文本执行；完整声明 `fuzzy_search_company_list`、`get_company_profile`、`get_direct_investment` 的专家可走平台固定的新华财经适配流程（模式 `xinhua_trial`）；完整声明平台全部八项能力的专家走平台的多层执行器（模式 `xinhua_panorama`），由平台实现穿透规则，技能文本只作为说明。缺少所需工具、声明额外未适配工具或未发布专项 skill 的导入项会显示缺失依赖并阻止运行；只声明部分全景能力时按一层执行，并在导入说明中提示。用户包不能指定 MCP 地址、密钥、代码或文件系统权限。
- MCP 工具采用服务端固定 allowlist，token 从 `XINHUA_MCP_API_KEY` 凭据组读取；远端地址固定在 `mcp.cnfic.com.cn` 的 HTTPS 主机范围。
- 2026-10-23 实测的工具契约（结构信息，未落盘原始响应）：`fuzzy_search_company_list` 的参数为 `keyword`（必填）、`limit`（1–50）、`offset`，返回 `{result:{total, results[], pagination{limit,offset,count,has_more,next_offset}}}`，候选含 `company_id`、`company_name`、`company_status_name`、`credit_code`、`address`、`start_date`；`get_company_profile` 与 `get_direct_investment` 的 `time` 为可选对象，`time_field` 分别是 `start_date` 与 `capi_date`，不传则按滚动三年窗口过滤。
- 全景图专家使用到的其余能力的字段口径（依据随仓库的接口说明 PDF）：`get_company_profile` 返回 `company_status_name`、`company_type_name`、`econ_kind`、`scope`、`start_date`、`regist_capi`、`oper_name`、`original_name`；`get_direct_investment` 每行含 `record_id`、`company_id`、`company_name`、`stock_name`、`stock_percent`、`should_capi`、`should_capi_unit`、`shoud_date`、`capi_date`、`dates`、`is_del`；`get_company_shareholder` 返回 `stock_name`、`stock_type`、`stock_percent`、`should_capi` 等；`get_company_can_rev` 返回 `revocation_date`、`cancellation_date`；`get_history_company_name` 返回 `his_company_name` 与起止日期；`get_company_annual_report_base_info` 返回 `report_year`、`publish_date`、`company_status_name`、`is_invested`；`get_company_annual_report_investment_info` 返回 `report_year`、`publish_date`、`investee_company_name`。
- 任务可附最多 3 份 PDF、DOCX、PPTX 或 UTF-8 Markdown 材料，单份 5 MB、总计 10 MB；与任务在同一事务入库。提取文字按文件截断后作为不可信数据交给模型，报告列文件名及 SHA-256，且标明用户提供、未经独立核验。上传材料、任务、结果与产物仅本人可访问，七天后清理；任务结束后可提前删除材料。扫描 PDF 无文字层时任务明确失败。
- 每人最多同时有 2 个排队/运行/待选任务，每小时最多提交 10 个；客户端幂等键防止重复提交。单任务最多领取执行 3 次，每人每小时最多 6 次执行尝试；失败重试计入同一预算。任务用原子领取、5 分钟租约和 30 秒心跳保护，产物对每个任务唯一。
- 新增材料上传及自定义专家受控工具执行尚未经过真实环境端到端试用；仍需部署后核对权限、提取质量、工具响应和报告内容。一层投资底稿不能替代完整尽调复核，全景底稿同样不能替代人工复核。
