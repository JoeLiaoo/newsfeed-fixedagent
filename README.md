# 中信私募ai平台

公司内部使用的个性化资讯、GP 投资动向和固定任务专家平台。首版约 20 名员工使用；个人日报是登录后的首页，新闻日报及 GP 动向分别推送到员工自行绑定的个人微信。

## 当前状态

仓库目前处于 P0 可行性与开发准备阶段，尚无可运行的应用代码。需求基线见 [建设计划](docs/PLAN.md)，执行顺序和完成状态见 [分步骤实施计划](docs/IMPLEMENTATION.md)，已收到材料的静态盘点见 [P0 记录](docs/P0-STATUS.md)。后续每个开发 Agent 须遵守 [AGENTS.md](AGENTS.md)，留下 `docs/logs/` 日志并勾选已完成的任务。

## 首轮开发范围

| 阶段 | 主要产物 |
|---|---|
| P0 | DeepSeek 与新华财经 MCP 接入边界、微信可行性、实例只读盘点和可执行技术方案 |
| P1 | 基于 AIHOT 的资讯底座、账号审核、细分赛道订阅、信源采集及个人日报首页 |
| P2 | 基于 `reference/SKILL.md` 的对外投资核查专家适配版、专家上传校验、任务与产物管理 |
| P3 | GP 新增投资识别、赛道归类、个人微信绑定与两类定时推送 |
| P4 | 备份确认、旧应用清理、在原 `ai-work` 系统上部署、试用及运维交接 |

首轮模型使用 **DeepSeek API**，企业数据先接入 **新华财经 MCP**。`reference/SKILL.md` 原文依赖悟道 MCP，新华财经适配版会明确报告能力差异；其他数据源采购或接入由后续验证决定。`reference/` 中有新华财经接口说明和 GP 候选名单；AIHOT 原生资讯用于人工智能相关赛道的样例。

## 本地资料与安全

- 本地和上线服务器的凭据放在各自的 `.config/`；该目录被 Git 忽略。不要把密钥复制进源码、文档、日志或提交记录。部署时核对服务器上既有目录的实际路径及读取权限。
- 用户已在 Codex 云端环境变量和 GitHub Actions 仓库级 secrets 中分别配置 `DEEPSEEK_API_KEY`、`XINHUA_MCP_API_KEY`；仓库内尚未验证其可用性。后续代码优先读取同名环境变量，本地和上线服务器可回退读取各自的 `.config/`。Actions 工作流需显式引用 secret。
- 当前 `.config/` 下密钥文件扩展名为 `.json`，实际为原始文本；读取器应按文本处理。未来的环境变量示例只包含变量名，不包含真实值。
- `reference/` 中的试用接口说明及 GP 名单是开发输入；使用前核对数据源授权与主体身份。
- 目前尚无安装、构建或启动命令；P1 引入应用代码后，由负责的 Agent 在本节补上真实可执行的命令。

## 开发与交接

从 [实施计划](docs/IMPLEMENTATION.md) 中选择依赖已满足的未完成任务。每个 Agent 完成工作后，在 `docs/logs/` 留下日志，勾选相应任务并链接日志；被阻碍或未验证的任务保持未勾选。优先进行与改动直接相关的少量检查，不做全量测试。真实微信投递和业务结果由用户参与试用确认。

P4 前，用户会安排同事分别备份 `ai-work-mvp` 中的内容。备份完成并核对后，保留实例操作系统，仅清理旧应用及其数据；其他服务和数据不在清理范围内。
