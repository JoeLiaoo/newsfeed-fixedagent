# WX-B headless runner

The worker sends one JSON line `{type:"chat",id:"<uuid>",prompt:"…"}` to `/run/newsfeed-hermes/runner.sock`. The runner accepts no command, path, model, recipient, or user ID from the request. It returns `{ok,answer,usage}` or a generic error. Socket access is restricted by the `newsfeed-hermes` group. Append `deploy/hermes-headless-runner/compose.runner.yml` to the normal Compose files **only when installing B**, and set `HERMES_RUNNER_GID` to that host group's numeric GID. It adds that group to the worker container and mounts only the socket directory read-only. Never expose the socket through HTTP or TCP.

Install the service example as a systemd unit under a dedicated `newsfeed-hermes` user/group. In its root-owned, mode 0600 `/etc/newsfeed-hermes/runner.env`, set `HERMES_MODEL`, `HERMES_MODEL_BASE_URL`, `HERMES_MODEL_API_KEY` and optionally `HERMES_BIN`, `HERMES_RUNNER_SOCKET`, `HERMES_RUNNER_BASE`. The model route and key are operator configuration. The runner copies **only** the model key into the child environment; worker DB, iLink, and administrator credentials are never available to Hermes. The Compose worker mounts only `/run/newsfeed-hermes` read-only. Ensure the container worker's GID can connect to the mode 0660 socket; use `group_add` in the host override after checking its actual GID. Do not mount `/opt/hermes-agent`, the Docker socket, or SSH keys.

Each invocation creates a private home and cwd, configures `agent.disabled_toolsets: [all]`, and calls Hermes with `--usage-file` **before** `chat`. User text enters stdin only. Stdout/stderr go to files; the last successful `result.text` is accepted. A 45-second timeout kills the CLI process group, with a 2-second grace. **R1 choice (b):** Hermes may start a detached idle gateway inside this isolated home. Its configured idle exit is 60 seconds; it can remain briefly after a timeout. Old homes are removed after 180 seconds on the next request. The live `/opt/hermes-agent/home` gateway is never stopped or reused.

The service does not install skills, use Hermes Weixin, or grant tool access. Verify the installed CLI path/version and the B0 zero-tool contract before enabling the feature. Apply migrations `0203`–`0208`, install and start the runner, verify socket permission from the worker, then grant only selected employees (`INSERT INTO member_agent_grants(user_id) VALUES (...)`). Enable `P3_ILINK_AGENT_ENABLED=true` only after `P3_ILINK_READING_REPLIES_ENABLED`, `P3_DELIVERY_ENABLED`, and `MODEL_CALLS_ENABLED` are on. Disable the agent flag to roll back; A reading replies continue. Revoke with `DELETE FROM member_agent_grants WHERE user_id=...`; a later INSERT gives a new immutable grant ID, so an old run cannot regain send permission.

Usage counts include `total_including_auxiliary.api_calls`, including title generation. Each pending invocation reserves two calls against 30/hour, 100/day per employee and 2000/day globally. Unknown calls retain their reservation and are never automatically retried. Cost remains unknown if Hermes cannot price the provider. A model gateway with an enforced upstream budget is still needed before treating these limits as a hard provider-side cap.
